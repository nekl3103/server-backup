# Проверка сборки 1.7.7

Проверка выполнена 8–9 октября 2026 года.

## Выполнено

- Release-сборка SwiftUI для arm64 / macOS 14+, локальная подпись и проверка codesign.
- DMG HFS+/UDZO: штатная проверка CRC32 и открытие образа.
- Нативное окно и форма SSH просмотрены в macOS. Главный экран, обзор готовности, выбор папок галочками и панели хранилища в тёмном дизайне просмотрены в отдельной демонстрационной сборке. Демонстрационные данные явно помечены и не подтверждают подключение к рабочим серверам.
- Нативные тесты: AES-GCM/PBKDF2 экспорт и импорт, отказ при неверном пароле, валидация SSH, передача stdin без интерпретации оболочкой.
- Реальный SSH из macOS к изолированному Ubuntu 24.04: пароль через Keychain/askpass, зашифрованный приватный ключ, блокировка изменившегося host key. Повторная проверка с пробелами в пути known_hosts прошла.
- 96 серверных unit-тестов: права конфигурации, защита идентификаторов, блокировки репозиториев, отсутствие/неверный UUID диска, отказ при неверном пароле без переинициализации, восстановление только записанных контейнеров, сохранение ошибок, отказ для нетранзакционных таблиц, неполная копия без очистки, проверка свободного места, watchdog сохранение даты создания при изменении расписания, отсутствие перезапуска контейнеров в dry-run и исключение секретов запросов операций.
- Реальный Restic в Ubuntu: две версии файла, дедупликация неизменённого файла, исключения, пробелы/кавычки/спецсимволы в именах, восстановление обеих версий, `check --read-data`.
- SFTP с реальным SSH-сервером и проверкой отпечатка; отказ при неверном пароле репозитория и при изменении host key.
- S3-совместимый тестовый сервис Moto: создание репозитория, бэкап, проверяемое восстановление, copy из SFTP в S3.
- PostgreSQL 16, MariaDB 11 и MySQL 8.4 в отдельных тестовых контейнерах: дамп, удаление таблицы, импорт и проверка исходных данных.
- Независимый второй Linux-контейнер: восстановление файлов только по экспортированным доступам к S3, без состояния исходного сервера.
- Docker: остановка выбранного контейнера перед бэкапом, перезапуск после успеха и ошибки, сохранение/восстановление named volume и импорт его содержимого.

Изолированный Ubuntu 24.04: получен реальный каталог пакетов dpkg, список установленных служб и системные/периодические cron-файлы. Недоступный systemd отображён отдельной ошибкой. Реальный `nginx -t` подтвердил сохранение корректного файла и откат неверного с сохранением прав; копии конфигурации имеют права 0600. Для этого теста доступность службы подставлена, поскольку systemd не был PID 1. Проверяется активная конфигурация, а не каждый неиспользуемый файл отдельно.

Программы и Cron: тесты ограничения файлов и служб, отказа при изменённом файле, атомарного сохранения с прежними правами, отката при ошибке проверки, резервной копии 0600 без содержимого в истории, защиты JSON, подтверждения действий, установленных/удерживаемых пакетов, пользовательских и системных crontab, периодических каталогов, Anacron и недоступных таймеров.

Обзор: unit-тесты подтверждают получение сохранённых настроек и истории без секретов; пустая конфигурация не выдаётся за завершённую настройку.

SMTP: unit-тесты STARTTLS, адресатов, изоляции ошибок, раздельных настроек успешных уведомлений, защиты заголовков и отключённых каналов. Журнал: проверены редактирование секретов и отказ для подставного имени службы.

Тестовые контейнеры и хранилища отдельные; рабочие серверы пользователя не использовались.

Графики и просмотр логов проверены в нативной демонстрационной сборке. Шесть тестов чтения логов проверяют отказ для внешних путей, ссылок, бинарных файлов и архивов, ограничение объёма и сохранение специальных символов в именах. Нативный тест проверяет преобразование числовых JSON-метрик, нулевую нагрузку, пропущенные показатели и сброс истории при смене сервера. Просмотр реальных логов и графиков рабочего сервера пользователя не выполнялся.

Яндекс Диск: восемь тестов проверили сырые/JSON OAuth-токены, защиту путей, отсутствие токена в аргументах, ошибку зависимости, квоту, отказ сохранения при ошибке доступа и маскирование секретов. Также проверено атомарное обновление помощника без изменений сохранённых заданий. В Ubuntu 24.04 реальный rclone 1.60.1 распознал remote Yandex из переменных окружения. Реальный мост Restic/rclone с локальным тестовым remote выполнил две копии, дедупликацию, восстановление обеих версий и полную проверку репозитория. Этот тест проверяет транспорт Restic/rclone, а не Яндекс API.

## Проверки семи новых функций

- 15 новых тестов: свежесть успешных копий, отключённые задания, выборка файлов и лимиты, прогноз с недостаточными/отрицательными данными, календарь без dry-run, принадлежность версии конфигурации нужному файлу, подтверждение возврата, строгий SSH наблюдателя, обнаружение отказа, ограничение повторных уведомлений и серверный запуск проверки восстановления.
- Реальный Restic в изолированном Ubuntu: два бэкапа, автоматическая проверка после каждого, проверка предыдущей копии, SHA-256, временная очистка, имена с кавычками, квадратными скобками и обратной косой чертой. История календаря и свежесть проверены по этим результатам.
- Реальный Nginx: сохранение версии, возврат оригинала с `nginx -t`, сохранение вытесненной версии. Доступность службы для этого теста подставлена, поскольку systemd не был PID 1.
- Два отдельных Ubuntu-контейнера: SSH-наблюдатель получил состояние источника, игнорировал попытку произвольной команды по принудительному ключу, обнаружил остановку и восстановление источника. Отправка уведомлений заменена тестовым обработчиком; реальные сообщения не отправлялись.
- Нативный SSH из .app повторно проверен с паролем, зашифрованным ключом, отказом для изменённого host key и путём с пробелами. Новый протокол передаёт исходник и запрос через stdin, не через длинный аргумент оболочки.
- Встроен официальный rclone 1.75.1 для Apple Silicon; ZIP проверен по SHA-256 официального источника, лицензия сохранена. Команда авторизации проверена через `--help`, parser токена — нативным тестом.

- В отдельной нативной демонстрационной сборке 1.5 просмотрены общий статус серверов, календарь, проверка восстановления, график роста хранилища, внешний контроль и историю со сравнением конфигураций. Это проверка интерфейса на демонстрационных данных.

## Не проверено на живой инфраструктуре

- Полный вход в Яндекс через браузер и получение настоящего токена: аккаунт не использовался.
- Ежедневное накопление размеров и прогноз на настоящей истории за несколько дней: расчёты проверены тестовыми рядами; результат является оценкой.

- Яндекс Диск с настоящим OAuth-токеном: учётная запись не предоставлена; квоты, авторизация, загрузка и восстановление через Яндекс API не подтверждены.

- Реальный облачный S3 с конкретными IAM-правами, HTTPS и тарифами; Moto проверяет совместимость протокола, не инфраструктуру провайдера.
- Подключение физического/виртуального диска с UUID: проверки отказа покрыты тестами, полноценный отдельный блочный диск не использовался.
- systemd как PID 1, выполнение суточного расписания, перезагрузка сервера и восстановление после выключения питания. Генерация служб и таймеров проверена, но тестовый Ubuntu-контейнер не загрузился с systemd.
- Telegram с настоящим ботом и chat ID: обработка ошибки отправки и watchdog покрыты тестами; реальные сообщения не отправлялись.
- Почта с настоящим SMTP-сервисом: реальные письма не отправлялись.
- Управление живыми systemd-службами и редактирование конфигураций рабочих программ: изменения на серверах пользователя не выполнялись.
- Полный перенос рабочих сайтов на другой сервер и производственные объёмы данных.
- Нотариальное заверение Apple и запуск на Intel: поставка предназначена для Apple Silicon с локальной подписью.

Эти ограничения не следует трактовать как подтверждённое аварийное восстановление производственного сервера. Перед включением ежедневных заданий выполните пробную копию и восстановление своих данных.

Демонстрационные данные не подтверждают подключение или установку на рабочем сервере.

Результат: `AUTOMATIC RECONNECTION AFTER CONTAINER RESTART PASSED`.

## Исправление Яндекс Диска 1.6.1

- Обнаружено удаление refresh_token и expiry при нормализации OAuth JSON в 1.6.0 и предыдущих версиях. Полный JSON теперь сохраняется в настройках репозитория и передаётся rclone; старый одиночный access_token отклоняется с инструкцией повторного входа.
- 98 серверных тестов прошли, включая сохранение refresh_token/expiry, проверку токена без refresh_token и безопасную диагностику авторизации, прав, сети и тайм-аута.
- Настоящий rclone 1.60.1 в отдельном Ubuntu 24.04 без сети воспроизвёл ошибку Unable to get RefreshToken на прежнем усечённом токене. Исправленный полный JSON прошёл инициализацию OAuth и дошёл до намеренно недоступного локального прокси. Проверка: tests/integration_yandex_token.py; результат: yandex-token-regression.log.
- Реальная квота, создание репозитория и OAuth-обновление в аккаунте Яндекса пользователя не проверялись; реальный токен не использовался.

## Исправление формата OAuth 1.6.2

- Излишне строгий алфавит токенов в 1.6.1 отклонял двоеточия в штатном refresh_token Яндекса. Токены теперь проверяются как непрозрачные строки без пробелов и управляющих символов с ограничением длины; сохраняются без изменения. Формат со знаками : и = проходит сохранение и передачу в rclone.
- 100 серверных тестов: дополнительно проверены сохранение refresh_token со штатными разделителями Яндекса, сохранение всего JSON, передача в окружение rclone и отказ для управляющих символов/слишком длинных значений.
- Формат сверён с официальным примером Яндекс OAuth: https://yandex.com/dev/id/doc/en/codes/screen-code . Реальный аккаунт пользователя не использовался.
